# rassylka — бот и мини-апп для рассылок со своего аккаунта

Бот подключает ваш аккаунт Telegram — по номеру или из tdata — и
рассылает от его имени по выбранным чатам, папкам и личным сообщениям:
чат за чатом, с заданной паузой. Управление целиком в мини-аппе.

Что уже работает:

* `/start` → меню с двумя кнопками: **Открыть приложение** и
  **Поддержка** (плюс «Как это работает»). Приложение открывается и с
  кнопки у поля ввода — та не уезжает вверх по переписке.
* В приложении — вход по номеру: номер → код из Telegram → облачный
  пароль, если он стоит на аккаунте.
* **Импорт из tdata**: zip с папкой Telegram Desktop — аккаунт
  подключается без номера и кода. В одной tdata может быть несколько
  аккаунтов, подключатся все.
* Список подключённых аккаунтов: живой / не работает, кнопки
  «Проверить» и «Отключить» (с отзывом сессии в Telegram).
* **Рассылка**: выбираете чаты (или папку Telegram), пишете сообщение,
  задаёте интервал — аккаунт пишет по кругу, чат за чатом. Пауза,
  продолжение, журнал отправок по каждому чату.
* Пробный период 5 дней от первого `/start`; на бесплатном тарифе в
  конец каждого сообщения дописывается строка о боте.

## Как работает рассылка

У рассылки есть список чатов, текст и интервал. Движок берёт
**следующий чат по кругу**, отправляет туда сообщение и назначает
следующую отправку через интервал. Дошёл до конца списка — начинает
сначала.

Интервал — это пауза **между сообщениями**, а не между кругами. Круг по
десяти чатам с интервалом в 15 минут займёт два с половиной часа; в
приложении это подписано прямо под списком выбранных чатов.

Папка Telegram разворачивается в список чатов при каждой отправке.
Добавили чат в папку в клиенте — он попадёт в круг после ближайшего
«Обновить список чатов». Папки, собранные правилом («все группы»),
тоже работают: правило применяется к вычитанным диалогам.

Всё идёт одной очередью, а не задачей на чат. Telegram считает
сообщения аккаунта, а не рассылки: параллельная отправка в десять чатов
разом — ровно тот всплеск, за который выдают ограничения. В любой момент
идёт одна отправка, между любыми двумя — пауза, общая на аккаунт, даже
если рассылок у него несколько.

### Тормоза, которые нельзя обойти из интерфейса

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `MIN_INTERVAL` | 60 с | Минимальный интервал. Меньше — заявка на блокировку |
| `ACCOUNT_MIN_GAP` | 20 с | Разрыв между любыми сообщениями одного аккаунта |
| `DAILY_LIMIT` | 200 | Потолок за сутки на аккаунт, считается по журналу |
| `INTERVAL_JITTER` | 0.2 | Разброс паузы ±20%: ровный ритм виден издалека |

### Что происходит при ошибках Telegram

* **Нельзя писать в чат** (нет прав, бан, чат закрыт) — чат
  отмечается в журнале, круг едет дальше.
* **FloodWait** — молчит **весь аккаунт** столько, сколько просят:
  ограничение выдано аккаунту, и остальные его рассылки замолкают тоже.
  Пауза лежит в базе и переживает перезапуск.
* **Медленный режим** в чате — ждём ровно столько, сколько он требует.
* **PeerFlood** — Telegram счёл поведение спамом. Все рассылки аккаунта
  останавливаются на сутки, человеку уходит сообщение. Продолжать в
  этот момент — идти к блокировке номера.
* **Сессия отозвана** — аккаунт помечается мёртвым, рассылки встают,
  человеку приходит просьба подключить заново.

## Что нужно

* **Python 3.10+**.
* **Токен бота** от @BotFather.
* **Ключи MTProto** — `api_id` и `api_hash` с
  [my.telegram.org](https://my.telegram.org), раздел *API development
  tools*. Выдают бесплатно. Без них вход по номеру не работает: Bot API
  так не умеет в принципе, это MTProto.
* **https-адрес** для мини-аппа. Telegram открывает WebApp только по
  https — ни http, ни localhost клиент не примет.

## Установка

```bash
cd rassylka
python -m venv .venv && .venv/Scripts/activate
pip install -r requirements.txt
cp .env.example .env        # заполнить BOT_TOKEN, OWNER_ID, ключи
python main.py
```

Проверить сборку без Telegram:

```bash
python selfcheck.py
```

### Адрес для мини-аппа

На своей машине проще всего туннелем:

```bash
cloudflared tunnel --url http://localhost:8080
```

Он выдаст адрес вида `https://что-то.trycloudflare.com` — его в
`WEBAPP_URL`, и перезапустить бота. Пока `WEBAPP_URL` пуст или начинается
не с `https://`, кнопки «Открыть приложение» в меню **не будет**: кнопка
с неподходящим адресом молча не открывается, а это хуже, чем её
отсутствие. Причину бот пишет в лог при старте.

На хостинге в `WEBAPP_URL` идёт домен, а `PORT` обычно приходит от
хостинга сам.

## Деплой на хостинг (bothost и подобные)

В репозитории лежит `Dockerfile`, и он там не для красоты. Без него
автоопределение хостинга находит `webapp/app.js`, решает, что проект на
Node, и запускает браузерный код мини-аппа через Node — тот падает на
первой строке с `window is not defined` и уходит в цикл перезапусков,
а `main.py` не стартует вовсе. С Dockerfile запускается только `python
main.py`.

Переменные окружения задаются в панели хостинга, файл `.env` туда не
кладут:

| Переменная | Что писать |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `OWNER_ID` | ваш числовой id |
| `MTPROTO_API_ID`, `MTPROTO_API_HASH` | ключи с my.telegram.org |
| `WEBAPP_URL` | домен, который хостинг выдал боту, целиком с `https://` |
| `SESSION_KEY` | **обязательно, см. ниже** |
| `SUPPORT_USERNAME` | ник поддержки |
| `DATA_DIR` | путь к подключённому тому, если хостинг его даёт |

`PORT` хостинг обычно передаёт сам, и `config.py` его слушает.

### Про `SESSION_KEY` на хостинге — это важно

Локально пустой `SESSION_KEY` безобиден: ключ создаётся файлом и лежит
рядом с базой. **На хостинге так делать нельзя.** Файловая система
контейнера одноразовая: при каждом передеплое ключ сгенерируется заново,
а старые сессии станут нечитаемыми — все подключённые аккаунты разом
покажутся как «не работает», и людям придётся вводить номер и код
сначала. То же самое с базой: без тома в `DATA_DIR` она обнуляется
вместе с подписками.

Поэтому ключ генерируется один раз и вписывается в переменную:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

## Как устроено

```
main.py        запуск: база, веб-сервер, движок рассылки, поллинг
handlers.py    /start, меню, справка, /stats для владельца
keyboards.py   меню: кнопка приложения и кнопка поддержки
webapp.py      HTTP: раздача мини-аппа и его API, проверка initData
accounts.py    вход по номеру через Telethon, работа с сессиями
tdata.py       импорт аккаунтов из папки Telegram Desktop
chats.py       сканирование диалогов и папок аккаунта, кэш
broadcast.py   движок: круг по чатам, лимиты, разбор ошибок Telegram
crypto.py      шифрование строк сессий
db.py          люди, подписки, аккаунты, чаты, рассылки, журнал
webapp/        сама страница приложения (index.html, app.css, app.js)
```

**Бот и веб-сервер — один процесс, и это не экономия.** Незавершённый
вход по номеру — это живое подключение к Telegram: `phone_code_hash`
привязан к нему, и на новом подключении тот же код Telegram не примет.
Разнести API приложения и это подключение по разным процессам нельзя.
По той же причине бот не масштабируется в несколько воркеров.

**Кто открыл приложение — решает подпись, а не страница.** Telegram
отдаёт мини-аппу подписанную строку `initData`; проверить её может
только тот, у кого есть токен бота. `user_id` берётся оттуда и никогда —
из тела запроса. Без этой проверки любой дёрнул бы наш API и увидел
чужие номера. Проверку гоняет `selfcheck.py`, включая подмену `user` при
живой подписи.

**Сессии.** Строка сессии Telethon — это не логин с паролем, а готовый
ключ доступа: с ней читают переписку и пишут от имени аккаунта. Поэтому:

* в базе она лежит зашифрованной (Fernet), ключ — отдельно;
* файлов `.session` на диске не остаётся, ключ живёт в памяти и уезжает
  в базу уже зашифрованным;
* облачный пароль не сохраняется вообще: уходит в Telegram и
  забывается;
* «Отключить» не просто удаляет запись, а **отзывает сессию** в
  Telegram — иначе доступ остался бы живым, а у нас его уже нечем
  отозвать.

### Импорт из tdata

tdata — папка Telegram Desktop с ключами уже выполненного входа, лежит
рядом с `Telegram.exe`. Человек архивирует её в zip и прикрепляет в
приложении; при локальном код-пароле Desktop его спрашивают отдельно
(это не облачный пароль).

Разбирает формат [opentele](https://github.com/thedemons/opentele). Он
тянет за собой **PyQt5** — tdata написана сериализацией Qt, и читать её
без Qt нечем. Из-за этого образ тяжелеет примерно на 130 МБ, а на голом
Debian нужна системная `libglib2.0-0`; она ставится в `Dockerfile`, и
там же на сборке стоит `python -c "from opentele.td import TDesktop"` —
чтобы нехватка библиотек падала при сборке, а не всплывала у человека
после загрузки архива.

Импортируется opentele лениво: если библиотеки нет, отваливается только
загрузка tdata, а бот и вход по номеру работают как обычно — кнопка в
приложении в этом случае просто не показывается.

Что сделано с безопасностью:

* **Архив распаковывается с проверкой каждого пути.** Имя внутри zip —
  просто строка, и туда кладут `../../` или абсолютный путь: наивная
  распаковка такого архива пишет куда угодно на диске. Плюс потолки на
  размер распакованного и число файлов — от архивов-бомб.
* **Ни архив, ни распакованная tdata не задерживаются**: временная
  папка стирается сразу после импорта, в том числе когда он сорвался.
  Остаётся только строка сессии, зашифрованной.
* **Код-пароль не сохраняется** и в лог не пишется.

**Ключи запоминаются вместе с сессией.** Telegram Desktop выдавал её под
свой `api_id`, и подключаться к ней нашим — верный способ её потерять:
для Telegram это выглядит как угон, и сессию отзывают. Поэтому при
импорте параметры (`api_id`, `api_hash`, модель устройства) кладутся в
колонку `accounts.api`, и дальше аккаунт всегда ходит с ними.

Одно предупреждение по существу, не техническое. tdata — это формат, в
котором продают и передают готовые аккаунты; поддержав его, сервис
получает и тех, кто грузит купленные пачки. Такие аккаунты ловят
ограничения быстрее и жалуются чаще, а отвечать за это будет репутация
вашего бота. Это стоит держать в голове при выборе тарифов и лимитов.

### Ключ шифрования

Пустой `SESSION_KEY` означает, что ключ создастся сам файлом
`data/session.key`. Так проще запуститься, но ключ и база оказываются в
одном месте. На хостинге лучше сгенерировать ключ и вписать в
переменную окружения:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

**Потерять ключ = потерять все подключённые аккаунты**: расшифровать
сессии будет нечем, людям придётся входить по номеру заново. При
переезде переносите `DATA_DIR` целиком либо задайте `SESSION_KEY`.

## Лимиты и осторожность

Telegram считает частые сообщения незнакомым людям спамом и наказывает
за это **аккаунт человека**, а не бота: `FloodWait` на часы,
`PeerFlood`, дальше блокировка номера. Что уже заложено:

* `CODE_REQUESTS_PER_HOUR` — тормоз на запросы кода. Стоит **до**
  обращения к Telegram, потому что за частые попытки входа он выдаёт
  ограничение самому номеру. Счётчик лежит в базе, а не в памяти:
  перезапуск процесса не должен обнулять его и отправлять человека
  долбить Telegram заново.
* `MAX_ACCOUNTS` — несколько номеров у одного человека. Смысл не в
  объёме, а в том, что лимиты Telegram персональные: пока один аккаунт
  ждёт `FloodWait`, работает следующий.

Когда дойдёт до самой рассылки, к этому добавятся паузы между
сообщениями, дневной лимит на аккаунт и остановка по `PeerFlood`. И
отдельно, не как техническая деталь: рассылка по людям, которые её не
ждут, кончается жалобами и блокировкой аккаунта — того самого, который
человек подключил. Инструмент рассчитан на свою базу: клиентов,
подписчиков, участников своих чатов.

## Если что-то не так

**Кнопки «Открыть приложение» нет.** `WEBAPP_URL` пуст или не https.
Смотрите лог при старте — там написано прямо.

**Приложение открывается, но пишет «Откройте из бота».** Значит, страница
не получила `initData`: так бывает, если открыть адрес в обычном
браузере. Внутри Telegram это же сообщение означает, что подпись не
сошлась — чаще всего `BOT_TOKEN` в `.env` не от того бота, к которому
привязана кнопка.

**«Подключение аккаунтов пока не настроено».** Не заданы
`MTPROTO_API_ID` / `MTPROTO_API_HASH`.

**«Ключи Telegram на сервере не приняты».** Ключи заданы, но неверные —
проверьте, что `api_id` и `api_hash` скопированы с my.telegram.org
целиком и от одного приложения.

**Код не приходит.** Он приходит **в Telegram, в чат «Telegram»** на тот
же аккаунт — это не SMS. SMS Telegram присылает только когда у аккаунта
нет других активных сессий.

**Аккаунт в списке «не работает».** Сессию отозвали в Telegram
(Настройки → Устройства) либо сменился ключ шифрования. Нажмите
«Проверить», затем подключите заново.
